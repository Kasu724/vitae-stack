# Vitae Stack 0.1.0

This is the initial self-hosted MVP. It is intended for users who want to maintain approved career evidence, compare that evidence with a reviewed job description, create grounded resume and cover-letter suggestions, review every change, run explainable estimated ATS checks, and export or delete their data.

## Included

- Structured Career Information Bank with immutable approved evidence and source locators.
- Resume and cover-letter libraries with immutable versions, autosaved drafts, claim provenance, locks, and explicit suggestion review.
- PDF, DOCX, Markdown, text, and project-JSON import with human extraction approval.
- Pasted text, file, and SSRF-constrained public-URL job ingestion with requirement review and evidence mapping.
- OpenAI-compatible and Ollama provider adapters; operators/users provide credentials and model access.
- Evidence-grounded resume and cover-letter tailoring. Unsupported factual claims block final PDF/DOCX export until remediated.
- Deterministic, categorized ATS compatibility estimates with visible methodology and limitations.
- PDF, DOCX, Markdown, text, JSON, full portability archive, import dry run, source deletion, and permanent workspace deletion.

## Deployment and upgrade

Use the versioned source archive or the five GHCR images with `compose.yaml` plus `compose.production.yaml`; never expose the development Compose credentials. Copy the exact tag-plus-digest values from the attested `*.image.txt` release assets into the fields shown by `.env.production.example`, configure fresh secrets, run the migration tools image once, and require `/api/ready` before traffic. This initial release has no prior application version to upgrade from. Future upgrades require a verified paired database/artifact backup and forward-only migration review.

## Security, privacy, and accessibility

Imported documents, URLs, templates, prompts, and model outputs are untrusted. Project telemetry is disabled, user content is not used for training by this project, secrets are excluded from archives/logs, and remote providers receive only disclosed bounded task context. The target is WCAG 2.2 AA; the published release requires the manual matrix in the accessibility validation record to be complete.

## Limitations

- ATS analysis is an estimate and does not reproduce or guarantee behavior from a proprietary ATS.
- OCR, job-board scraping/application submission, shared workspaces, public registration, OIDC/social login, custom templates, and hosted inference are outside this MVP.
- English (US and locale-neutral dates) is the initial ATS ruleset. Local model quality varies and is not promised to match remote models.
- Filesystem artifacts and a single-host Compose stack are the reference deployment; multi-node/HA and S3-compatible storage are not release-certified.

Verify `SHA256SUMS`, GitHub artifact attestations, image SBOM/provenance, and the signed annotated tag before installation. Review `SECURITY.md` and the backup/restore runbook before storing personal data.
