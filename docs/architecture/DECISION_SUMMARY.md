# Foundation decision summary

This index resolves the product's required foundation questions; linked documents contain the normative detail.

|   # | Decision                                                                                                                                                                                                                                                                                                                                   |
| --: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
|   1 | MVP supports personal single-user and closed-registration multi-user deployments with one isolated workspace per user; shared workspaces are excluded. [Auth ADR](../adr/0005-authentication-modes.md)                                                                                                                                     |
|   2 | Simplest secure auth is Better Auth email/password with benchmarked scrypt and database sessions; `trusted-local` is loopback-only and fails closed. [Authentication](AUTHENTICATION_AND_AUTHORIZATION.md)                                                                                                                                 |
|   3 | Source/export bytes use a private mounted filesystem by default; S3-compatible storage is optional; PostgreSQL stores metadata. [Storage ADR](../adr/0006-artifact-storage.md)                                                                                                                                                             |
|   4 | Development runs app/worker on host with Docker PostgreSQL or full Compose; production uses nonroot app/worker/PostgreSQL containers, TLS proxy, persistent storage, backups, and password auth. [Deployment](DEPLOYMENT.md)                                                                                                               |
|   5 | Provider configurations are workspace-owned; keys are environment references or write-only AES-256-GCM envelopes under an external master key and never reach clients/logs. [Secrets](../security/SECRET_MANAGEMENT.md)                                                                                                                    |
|   6 | MVP provider paths are generic OpenAI-compatible (including OpenAI preset) and Ollama; no hosted model is required. [Provider support](../ai/MODEL_PROVIDER_SUPPORT.md)                                                                                                                                                                    |
|   7 | Outputs use closed JSON schemas derived from Zod, local semantic/provenance validation, and at most two bounded repair attempts; hard safety failures are not retried by relaxing constraints. [Schemas](../ai/STRUCTURED_OUTPUT_SCHEMAS.md)                                                                                               |
|   8 | Facts are proposals until approval; approved facts are immutable, corrections supersede, withdrawal excludes future use, and deletion previews/cascades dependents. [Career-model ADR](../adr/0007-structured-career-model.md)                                                                                                             |
|   9 | Each document version snapshots claims and evidence links; unchanged edits retain anchors, changed factual spans become unverified. [Provenance](PROVENANCE_MODEL.md)                                                                                                                                                                      |
|  10 | Manual factual edits can be saved as unverified drafts but require linked/approved evidence before final export. [Editor behavior](../design/EDITOR_BEHAVIOR.md)                                                                                                                                                                           |
|  11 | ATS rules and numbers are deterministic/versioned; optional AI only explains fixed findings. [ATS ADR](../adr/0010-deterministic-ats.md)                                                                                                                                                                                                   |
|  12 | PDF imports use embedded-text extraction with no MVP OCR; DOCX is parsed as untrusted ZIP/XML; export uses bounded tagged PDFKit and structured `docx` renderers behind a fixed no-network template. [Document pipeline](DOCUMENT_PIPELINE.md), [export](EXPORT_PIPELINE.md), [renderer ADR](../adr/0018-tagged-pdf-and-docx-renderers.md) |
|  13 | Job URLs use a dedicated HTTPS fetcher with public-address resolution/pinning, per-redirect revalidation, strict byte/time/type limits, no credentials/subresources/JavaScript, and paste fallback. [SSRF ADR](../adr/0017-ssrf-safe-url-fetching.md)                                                                                      |
|  14 | Users receive versioned archive export; permanent workspace deletion freezes writes, erases/verifies active data within 24 hours, and backup expiry is at most 30 days. [Retention](../security/DATA_RETENTION_AND_DELETION.md)                                                                                                            |
|  15 | Standard Node/Docker/PostgreSQL, provider/storage/auth interfaces, portable archive schemas, and no mandatory SaaS avoid proprietary lock-in. [Architecture](../../ARCHITECTURE.md)                                                                                                                                                        |
|  16 | MVP excludes application submission/scraping, OCR, collaboration/public signup/OIDC, native apps, proprietary ATS emulation, training on user data, custom executable templates, microservices, and vector infrastructure. [Non-goals](../product/NON_GOALS.md)                                                                            |
|  17 | Release readiness requires AC-001–028, M01–M22, security/provenance/isolation/deletion/accessibility gates, clean Compose install, tested upgrade/restore/rollback, and visible limitations. [MVP scope](../product/MVP_SCOPE.md)                                                                                                          |
