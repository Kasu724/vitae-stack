# AI task catalog

Each task has a stable ID, versioned prompt/schema, capability profile, evaluation dataset, and deterministic postconditions.

| Task                               | Input                                          | Output                                                        | Deterministic boundary                                                                     |
| ---------------------------------- | ---------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| AI-01 Career-fact extraction       | Sanitized source text with locators            | Proposed entries/facts/skills and exact source spans          | File safety, locator validity, schema; proposals require approval                          |
| AI-02 Job requirement extraction   | Normalized job snapshot                        | Categorized requirements, priority, source spans, ambiguities | Source-span validity; user review creates authoritative revision                           |
| AI-03 Evidence retrieval           | Requirement + approved fact index              | Candidate evidence IDs/reasons                                | Workspace/status filter and lexical candidate set are deterministic; model cannot add IDs  |
| AI-04 Requirement-evidence ranking | Requirement + bounded candidates               | Ordered candidate IDs and rationale                           | ID subset, value/date contradiction, and strength calculation checked locally              |
| AI-05 Resume section selection     | Requirements + selected facts + source outline | Include/order operations                                      | Locks, allowed sections, evidence coverage enforced locally                                |
| AI-06 Bullet revision              | One bullet, requirement IDs, evidence facts    | Atomic replacement + factual claims/citations                 | Exact ID and semantic entailment; metrics/dates checked                                    |
| AI-07 Cover-letter planning        | Job + selected evidence                        | Paragraph purposes, requirement/evidence IDs                  | No prose facts; all IDs subset-checked                                                     |
| AI-08 Cover-letter drafting        | Approved plan + evidence                       | Paragraphs with claim spans/citations                         | Claim coverage and conflicts checked; unsupported text rejected                            |
| AI-09 Change explanation           | Before/after + evidence/requirements           | Concise rationale                                             | Cannot modify suggestion or cite new IDs                                                   |
| AI-10 Quality feedback             | Canonical document + rules context             | Nonfactual style suggestions                                  | No score, fact insertion, or automatic persistence                                         |
| AI-11 ATS analysis                 | Resume text + optional reviewed job source     | Overall estimate, weighted categories, rationales, findings   | Closed schema, context-specific categories and score/weight bounds; no grounding authority |

AI-03 uses no model by default for small banks; SQLite lexical retrieval and structured filters may be sufficient. AI-05–08 are mandatory for the resume/cover-letter generation commands: without an eligible configured model those commands remain unavailable. Users may still edit documents manually and use versions, ATS, export, and every non-generation workflow. Each task records provider/model alias, prompt/schema version, input/output hashes, attempts, finish state, and usage—not raw prompts in logs.

M16 requires AI-11 through an available structured-output provider. The UI discloses that the selected resume text and optional reviewed job source are sent to that provider. `ai-11.v1` returns the overall estimate, rationale, category scores and weights, findings, location hints, and remediation. Local validation enforces exact categories for job/no-job context, bounded values, unique categories, and weights totaling 100. It does not calculate a fallback score. Stored reports record provider/model/task/input/output provenance. AI results never affect claim support or export eligibility.

M11 currently implements AI-03's retrieval objective as deterministic `lexical-evidence@1` and does not invoke AI-03 or AI-04 model adapters. This is an intentional MVP path, not a silent fallback: each run exposes its algorithm version, signals, score, and candidate lifecycle state. A future optional reranker may only reorder the already persisted candidate IDs and cannot introduce facts.

M07 recommends AI-01 extraction through a tested provider with an assigned model. AI-01 receives only the bounded extracted source text as a catalog of precomputed exact single-line UTF-16 title/fact slices, then returns closed-schema entry classifications, stable item keys, and copied slice spans. Local code derives canonical sections from entry types, verifies every source slice and item grouping, rechecks the immutable source hash, stores provider/model/attempt/hash metadata without raw prompts or output, and creates pending item-bound proposals only. Invalid output persists nothing and never silently falls back. The provider-independent `deterministic-sections@2` fallback recognizes common headings and blank-line item boundaries, marks its grouping heuristic, and still requires full review.

M10 invokes AI-02 only through an available provider configuration with an assigned model. Its closed `ai-02.v1` result contains at most 200 categorized requirements and bounded warnings. Every model-created item must include exact UTF-16 start/end offsets and an exact source-text slice from the stored normalized job revision; missing or mismatched locators are hard failures and are never repaired by relaxing validation. Deterministic line proposals and an empty manual review remain available without a provider. Finalization requires a decision for every proposal and creates an immutable reviewed revision.

M13 requires an eligible AI-05/AI-06 model. It invokes AI-05 once per new resume run and AI-06 once per eligible, unlocked block, with a deterministic maximum of five concise or ten standard blocks. Inputs are limited to the pinned resume outline/block, bounded reviewed job text, accepted requirements, explicitly included direct/combined evidence matches grouped by career section/item, and writing preferences. Approved bullet and detailed-context evidence is bounded to 40,000 characters across the run context. Local validation rejects unknown sections, blocks, requirements, or facts; overlapping, out-of-range, or incomplete claim coverage; evidence without strong support; low lexical entailment; and changed numeric tokens. The run persists content hashes, task versions, provider/model metadata, attempts, output hashes, selected evidence, derived protected block IDs, and immutable suggestions. It never mutates the document and has no deterministic generation fallback.

M14 requires an eligible AI-07/AI-08 model. AI-07 runs once per new cover-letter run and returns only paragraph purposes and allowed block/requirement/evidence IDs; it cannot return prose. AI-08 receives one planned paragraph's selected requirements and approved evidence grouped by career item, never the raw job snapshot, and its entire non-punctuation output must be covered by evidence-linked claim spans under the same numeric, entailment, and strong-match gates as AI-06. Empty salutation and closing blocks may receive only repository-owned exact generic phrases from `deterministic-letter-framing@1`; these phrases are framing, not a generation fallback. The model cannot generate company descriptions, role names, contacts, addresses, salutations, or unsupported enthusiasm as unclassified framing.
