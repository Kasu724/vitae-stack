# Product requirements

All requirements below are MVP unless marked otherwise. Detailed, testable examples are in [acceptance criteria](ACCEPTANCE_CRITERIA.md); delivery mappings are in [traceability](../exec-plans/REQUIREMENTS_TRACEABILITY.md).

## Career data and documents

- **PR-001 Career Information Bank:** A workspace shall own profiles, section-grouped career items, approved facts, skills, goals, preferences, sources, and reusable documents; users can search, filter, inspect provenance, and export them. Canonical sections include experience, projects, education, skills, research/publications, leadership/service, certifications, awards/accomplishments, and additional information.
- **PR-002 Structured entries:** Each Career Information Bank section contains zero or more distinct items. Users can create work, internship, project, research, education, certification, award, leadership, extracurricular, volunteering, coursework, publication, accomplishment, metric, skill, and custom items with typed dates, organization/school, location, item notes, tags, and applicable typed attributes such as major, minor, relevant courses, honors, and technologies. Each item owns its proposed and approved bullets, detailed factual context, and other evidence; facts from separate items never share an implicit identity.
- **PR-003 Evidence lifecycle:** Extracted or manually entered facts begin as proposals. Approval creates immutable evidence IDs. Corrections supersede rather than mutate approved facts; withdrawal prevents future use; permanent deletion removes dependent claims/versions according to an explicit impact preview.
- **PR-004 Document library:** Users can store multiple resumes and cover letters, label them, choose source versions, archive, restore, or permanently delete whole document aggregates directly from library cards, apply an action to a selected group after a named confirmation and dependency preview, and save tailored outputs back to the library. Individual immutable versions cannot be deleted separately.
- **PR-005 Versioning:** Every accepted suggestion, manual save, and tailoring result creates an immutable version with parent, author/action, timestamp, and provenance snapshot; users can compare and restore by creating a new version.

## Ingestion and analysis

- **PR-006 Document import:** Accept PDF, DOCX, Markdown, plain text, and versioned project JSON within allowlisted MIME/signature/size limits. Parse on the server without executing embedded content, macros, scripts, links, or templates.
- **PR-007 Extraction approval:** Resume extraction separates the source into canonical sections, distinct items within each section, and item-bound facts/bullets before review. Structured AI extraction is the recommended primary path; a bounded deterministic section/item heuristic remains available without a provider. Display the hierarchy beside source locators and support editing, duplicate resolution, and checkbox-selected approve or reject decisions with visible-page and all-pending selection controls and a confirmation that names every selected proposal. Unapproved content cannot enter the Career Information Bank as generation evidence.
- **PR-008 Job input:** Accept pasted text, a public HTTPS URL, or an allowlisted file. Preserve the normalized job snapshot and input provenance. Users can archive/restore a job or permanently delete its complete aggregate after dependency preview and confirmation; individual immutable revisions cannot be deleted.
- **PR-009 Secure URL retrieval:** Resolve and connect only to public addresses, revalidate every redirect, limit bytes/time/redirects/content types, send no user credentials, and return safe diagnostics.
- **PR-010 Requirement extraction:** Produce structured required/preferred qualifications, responsibilities, keywords, seniority, and ambiguities with source spans; validate schema and allow user correction.
- **PR-011 Evidence matching:** Map each requirement to zero or more approved evidence facts with deterministic lexical signals, optional model ranking, confidence/reason, and explicit gaps; users can include/exclude matches.

## Tailoring and editing

- **PR-012 Tailoring setup:** Users select source documents, job snapshot, entries, facts, sections, exclusions, locks, tone, and length before generation. Locked content cannot be changed by suggestions.
- **PR-013 Resume tailoring:** A configured, tested AI model is required to generate resume tailoring. The model compares selected career items, chooses the most relevant approved bullets and detailed factual context, and proposes section selection, ordering, bullet revisions, and additions using only selected approved facts, while preserving source version and explaining each change. There is no deterministic generation fallback.
- **PR-014 Cover-letter tailoring:** A configured, tested AI model is required to create an evidence-linked outline and draft using selected approved item evidence and job requirements; no generated factual claim may lack evidence. There is no deterministic generation fallback.
- **PR-015 Claim provenance:** Every factual generated span shall link to one or more immutable evidence IDs and the generating task/run; the link survives accepted edits and document versions.
- **PR-016 Unsupported-claim prevention:** Reject provider output with unknown, withdrawn, conflicting, or semantically insufficient citations. Unsupported factual manual edits remain visibly unverified and block final export until linked to or approved as evidence.
- **PR-017 Suggestion review:** Show atomic changes, explanation, affected text, job rationale, evidence, and conflicts; users can accept/reject individually or in a reviewed group and undo through version creation.
- **PR-018 Manual editing:** Provide resume and letter editors with autosaved drafts, explicit version save, plain-text paste, structured sections, and claim-level status. Manual factual changes invalidate affected provenance until re-established.

## Analysis, export, and control

- **PR-019 Estimated ATS analysis:** Require a configured, tested AI model assigned to AI-11 to analyze a saved resume or ready uploaded resume source. The user may run a general analysis without a job source or optionally compare the resume with a reviewed job source. Show the model-provided overall estimate, weighted category assessments, findings, remediation, provider/model/task provenance, input/output hashes, and limitations. Validate all model output against a closed schema. ATS output is advisory only and never controls factual grounding, claim support, export eligibility, or hiring decisions.
- **PR-020 Export:** Export final PDF, DOCX, Markdown, plain text, and structured JSON where the format supports the content. Use sanitized templates and reproducible rendering; block final export on unsupported factual claims and label any permitted draft artifact.
- **PR-021 Data portability:** Export a documented, versioned archive containing structured data, documents, provenance, settings (excluding secret values), sources when requested, and artifacts when requested; accept compatible project JSON with preview and conflict handling.
- **PR-022 Provider configuration:** Configure OpenAI-compatible and Ollama endpoints per user/workspace, test capabilities, choose a model for one, multiple, or all tasks, show data destination, and keep credentials server-side encrypted or environment-referenced. Users can permanently delete an unused provider configuration and its stored credential after explicit confirmation; a provider referenced by saved tailoring history is retained to preserve provenance.
- **PR-023 Deployment:** Ship a downloadable Windows x64 portable package with a bundled runtime, no sign-in, an automatically created local data folder, loopback-only access, SQLite plus local artifact files, and no required proprietary service or container/database installation.
- **PR-024 Privacy controls:** Show what content will be sent to a provider before a task, permit local-only providers, minimize prompts, disable project telemetry by default, and never use user content for project model training.
- **PR-025 Retention and deletion:** Users can archive or delete supported records directly from their library cards, select multiple records for a bulk archive/delete action, and review a confirmation that names every selected record and applicable dependency impact before mutation. Users can remove source binaries while retaining pending proposals, completed review decisions, and approved facts with source-unavailable markers; delete eligible career entries and their evidence graph; delete complete document aggregates and managed export artifacts; delete eligible whole-job aggregates; or permanently delete all local application data through an explicit confirmation flow. Individual document versions and job revisions cannot be deleted separately; an entry supporting saved document claims, a document with an unexpected external history reference, and a job supporting an accepted document version block their respective record deletion. Every record-selection deletion is transactionally rechecked and all-or-nothing. Deletion receipts and audit metadata contain identifiers/status/counts, not content. Copies the user made outside the managed data folder are outside application control.
- **PR-026 Local access boundary:** The application has no accounts. It automatically provisions one local principal and workspace, binds only to loopback, rejects forwarded/non-loopback authorities, and fails closed if configured for remote access. Every object access remains scoped to that workspace as defense in depth.

## Quality attributes

- **PR-027 Security:** File, URL, HTML, prompt, model-output, authorization, secret, logging, dependency, and denial-of-service controls meet the documented threat-model acceptance tests.
- **PR-028 Reliability:** Jobs are idempotent, bounded, cancellable where safe, retry only known-transient failures, and expose recoverable states without duplicate versions/artifacts.
- **PR-029 Performance:** Meet the budgets in [performance budgets](../engineering/PERFORMANCE_BUDGETS.md) on reference hardware and representative fixtures.
