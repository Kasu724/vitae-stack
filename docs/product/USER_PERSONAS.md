# User personas

## P1 — Privacy-conscious job seeker

Maintains several resume variants and wants local or self-hosted control. Needs visible provider destinations, local-model support, complete export/deletion, and confidence that facts are not fabricated. May tolerate setup complexity but not silent data transmission.

## P2 — Active applicant

Tailors multiple applications per week. Needs fast job ingestion, reusable facts, evidence matching, atomic review, good keyboard flow, and version recovery. Values time saved only if review remains faster than rewriting.

## P3 — Career changer or early-career user

Has relevant projects, coursework, volunteering, and transferable skills that may not appear in a resume. Needs extraction guidance, gap visibility, and language improvements that do not overstate seniority or experience.

## P4 — Self-hosting operator

Runs the service for a household, school lab, or small community. Needs closed registration, per-user isolation, simple Compose deployment, backups, upgrades, resource limits, private storage, and no mandatory commercial services.

## P5 — Contributor/security reviewer

Needs explicit trust boundaries, deterministic rules, fixtures, stable interfaces, reproducible releases, and honest current-state documentation. Optimizes for maintainability and verifiable behavior rather than provider-specific features.

Accessibility is not a separate persona: each persona may use keyboard navigation, screen magnification, high contrast, reduced motion, voice control, or a screen reader.
